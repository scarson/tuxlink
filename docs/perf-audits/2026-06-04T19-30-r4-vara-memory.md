# R4 — VARA modem driver: memory & allocation audit

Agent: glade-knoll-shoal. Dimension: memory/allocation only. Read-only.
Scope: `src-tauri/src/winlink/modem/vara/*.rs` + `modem/process.rs`.
Load: ARQ at HF rates (LOW — sub-kbyte/s payload, cmd lines are sparse async events).
Lens prior: `rust.md` (memory). Model standard, Impact LOW (no wall-clock).

## Examined

- `wire.rs` — `LineReader::read_line` per-line buffer + `String::from_utf8`.
- `transport.rs` — send/recv/data_stream; no whole-body buffering in the modem subtree (B2F payload path is `data_stream()` raw `TcpStream`, not implemented here).
- `command.rs` — `OutboundCommand::as_wire` / `InboundCommand::parse` token allocs.
- `commands.rs` — `VaraStatus` snapshot clones (status path).
- `listener.rs` — `serve_inbound_one` / `set_listen` drain loop; `parse_peer_call`.
- `process.rs` — `confirm_audio_device_released` `lsof` output buffer.

## Findings

### [1] Per-line `Vec` allocated fresh on every `read_line` call
- **Location:** `wire.rs:32` (`let mut buf: Vec<u8> = Vec::new();` inside `read_line`).
- **Problem:** Each cmd-socket line read allocates a new growable `Vec`, fills it via `read_until`, then moves it into `String::from_utf8`. No buffer reuse across reads. The `serve_inbound_one` / `set_listen` drain loops call `recv()` → `read_line()` repeatedly (every read-timeout tick, default 2 s, plus per async event), so each PTT/BUFFER/IAMALIVE event and each idle-poll tick mallocs + frees one `Vec`.
- **Impact:** LOW. VARA cmd lines are short (tens of bytes) and arrive at human/ARQ cadence — a handful per second at most. The alloc is the dominant per-line cost only relative to itself; absolute rate is negligible. No wall-clock claim. Listed because it is clearly avoidable and on the only repeatedly-hit allocation path in the subtree.
- **Confidence:** High (alloc is real and per-call).
- **Effort:** Low. Hold a reusable `Vec<u8>` (or `String`) field on `LineReader`, `buf.clear()` + `read_until` into it each call, return an owned `String` only at the boundary — or keep the owned-`String` return but reuse the byte scratch. Note `read_until`'s `n==0` EOF check still works on a cleared buffer.
- **Verification:** Wrap `read_line` in a tight loop over a `Cursor` of many `\r`-lines under a heap profiler (dhat) and confirm allocation count drops from N-lines to ~1 after reuse.

## Suspected Bugs

None observed in the memory/allocation dimension.
